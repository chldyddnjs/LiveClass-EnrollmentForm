### 1. 배경 및 목적

강의 선택은 수강 신청 흐름의 진입점입니다. 사용자가 처음 마주치는 화면인 만큼 로딩 상태, 빈 상태, 에러 상태를 모두 고려해야 하고, 카테고리 필터와 페이지네이션이 URL 상태와 동기화되어야 합니다. 이 커밋은 강의 목록 페이지, 강의 상세 페이지, 신청 유형 선택 페이지를 구현하고, 이후 모든 페이지가 따를 라우팅 구조를 확립하는 것이 목적입니다.

---

### 2. 라우팅 구조 결정

라우트 충돌 문제를 해결하는 과정에서 URL 구조를 변경했습니다. 초기 설계는 `/enroll/:courseId`로 동적 세그먼트를 사용했는데, 이 경우 `/enroll/complete`, `/enroll/step2` 등 고정 경로를 `courseId` 파라미터로 인식하는 문제가 발생했습니다. React Router는 등록 순서대로 매칭하므로 동적 세그먼트가 먼저 있으면 이후 고정 경로를 모두 가로챕니다.

이를 해결하기 위해 강의 신청 진입 경로를 `/courses/:courseId/enroll`로 변경했습니다. 강의 컨텍스트 안에 신청 액션이 있다는 의미로 URL이 더 명확해졌고, `/enroll/*` 하위 경로와 완전히 분리되어 충돌이 없습니다.

`/                        강의 목록
/courses/:id             강의 상세
/courses/:courseId/enroll  Step1 신청 유형 선택
/enroll/step2            Step2 신청자 정보
/enroll/step3            Step3 확인 및 제출
/enroll/complete         신청 완료` 

---

### 3. 카테고리 필터와 URL 동기화

카테고리 선택 상태를 `useState`가 아닌 URL 쿼리 파라미터(`?category=development`)로 관리했습니다.

이유는 세 가지입니다. 

1. 사용자가 강의 상세 페이지에서 뒤로가기로 돌아올 때 선택했던 카테고리가 유지됩니다. `useState`로 관리하면 컴포넌트가 언마운트되면서 상태가 초기화됩니다. 
2. 특정 카테고리 결과를 URL로 공유할 수 있습니다. 
3. TanStack Query의 캐시 키가 카테고리 값을 포함하므로 카테고리 전환 시 이전 결과가 캐시에서 즉시 복원됩니다.

카테고리 변경 시 페이지 번호는 1로 초기화합니다. 3페이지를 보다가 카테고리를 바꾸면 새 카테고리의 3페이지가 존재하지 않을 수 있기 때문입니다.

---

### 4. 페이지네이션을 URL이 아닌 로컬 상태로 관리한 이유

카테고리와 달리 페이지 번호는 `useState`로 관리했습니다. 페이지 번호는 공유하거나 북마크할 가치가 낮고, URL에 포함하면 뒤로가기 히스토리가 페이지 전환마다 쌓여 사용자가 목록을 떠나려면 여러 번 뒤로가기를 눌러야 합니다. 필터 조건(카테고리)은 URL, 탐색 상태(페이지)는 로컬로 분리하는 것이 일반적인 관행입니다.

---

### 5. Step1 → Step2 데이터 전달 방식

강의 신청 진입 시 `courseId`는 URL 파라미터에서 읽고(`useParams`), 신청 유형(`enrollmentType`)은 Zustand store에 저장한 뒤 Step2로 이동합니다.

Zustand를 선택한 근거는 세 가지입니다. 

1. 다단계 폼 전체에 걸친 상태를 프로퍼티 드릴링 없이 어느 컴포넌트에서도 접근할 수 있습니다. 
2. `persist` 미들웨어로 새로고침 후에도 입력 데이터를 복원할 수 있습니다. 셋째, 셀렉터 기반 구독으로 필요한 상태가 바뀔 때만 리렌더링됩니다. React Router `state`는 새로고침 시 소실되고, URL 파라미터는 신청 흐름 중간 단계를 직접 접근하는 시나리오를 허용해 데이터 정합성 보장이 어렵습니다.

### 6. 비동기 상태 분기 처리 원칙

강의 목록 페이지는 네 가지 상태를 모두 처리합니다.

로딩 상태에서는 스켈레톤 카드 6개를 실제 카드와 동일한 레이아웃으로 표시합니다. 빈 화면 대신 스켈레톤을 쓰는 이유는 레이아웃 시프트 없이 콘텐츠가 채워지는 느낌을 주기 위함입니다. 

에러 상태에서는 재시도를 유도하는 메시지를 표시하며, TanStack Query의 `retry: 1` 설정으로 자동 1회 재시도 후 에러 상태로 전환됩니다. 빈 상태는 카테고리에 강의가 없을 때 별도 안내를 표시합니다. 

에러와 빈 상태를 같은 UI로 처리하면 사용자가 시스템 오류로 오해할 수 있어 분리했습니다. 성공 상태에서는 카드 그리드와 페이지네이션을 표시합니다.

### 7. 잔여석고 기준 설정

잔여석 5석 이하를 경고 기준으로 설정했습니다. 이 숫자는 요구사항에 명시되지 않은 가정입니다. 단체 신청 최대 인원이 10명이므로, 단체 신청이 가능한 최소 잔여석(2명)과 최대 인원(10명)의 중간값 부근인 5를 기준으로 잡았습니다. 이 값은 `LOW_SEAT_THRESHOLD` 상수로 추출해 변경 시 한 곳만 수정하면 됩니다.
