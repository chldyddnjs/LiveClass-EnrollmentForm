### 1. 배경 및 목적

다단계 폼에서 스텝 간 데이터를 공유하고, 뒤로가기 후 입력값을 복원하며, 개인/단체 전환 시 데이터 정합성을 보장하는 것이 이 커밋의 핵심 과제입니다.

---

### 2. 폼 컴포넌트 분리 전략 — key를 이용한 강제 리마운트

개인↔단체 신청 유형 전환 시 두 가지 문제가 있었습니다. 

1. 같은 URL(`/enroll/step2`)로 `navigate`해도 React Router가 컴포넌트를 리마운트하지 않아 `useForm`의 `defaultValues`가 재적용되지 않습니다. 
2. 단체 신청 입력 후 개인 신청으로 전환해도 store의 `step2`에 group 데이터가 남아있어 폼 초기값으로 그대로 들어갑니다.

이를 해결하기 위해 폼 로직을 `Step2Form` 컴포넌트로 분리하고, 페이지 컴포넌트에서 `<Step2Form key={currentType} />`으로 렌더링합니다. 

`currentType`이 바뀌면 React가 이전 컴포넌트를 언마운트하고 새로 마운트하므로 `useForm`이 처음부터 실행되어 `defaultValues`가 새로 적용됩니다.

`getDefaultValues`에서는 `step2?.enrollmentType === currentType`일 때만 store 값을 복원합니다. 

타입이 다르면 빈 값으로 시작하여 이전 단체 데이터가 개인 폼에 섞이지 않도록 합니다.

---

### 3. switchToPersonal 액션 설계

단체→개인 전환 시 group 데이터를 어떻게 처리할지 명시적으로 결정했습니다. 

`applicant` 공통 필드(이름, 이메일, 전화번호, 수강 동기)는 유지하고, `group` 데이터만 제거합니다. 

전환 전 확인 다이얼로그를 표시해 사용자가 데이터 초기화를 인지하도록 합니다.

---

### 4. 유효성 검증 시점 설계

| 시점 | 방식 | 대상 |
| --- | --- | --- |
| blur | RHF `mode: "onBlur"` | 개별 필드 |
| 인원수 입력 중 | `trigger` 수동 호출 | headCount 단독 |
| 스텝 이동 | `handleSubmit` | 해당 스텝 전체 |

`headCount`는 잔여석 초과 여부를 입력 즉시 알려줘야 하므로 `onChange`에서 `trigger`를 수동 호출합니다. 

Zod 스키마의 `.max(10)`은 정적 값이라 동적인 잔여석 검증을 할 수 없으므로 스키마에서 제거하고 RHF의 `validate` 함수에서 처리합니다.

---

### 5. headCount 검증 레이어 분리

`headCount` 검증은 두 레이어로 나뉩니다. 

1. Zod 스키마는 타입 안전성과 정적 규칙(2명 이상, 정수)을 담당하고, RHF `validate`는 동적 규칙(잔여석 초과 여부)을 담당합니다. 
2. Zod에 `.max()`를 남겨두면 Zod가 먼저 에러를 내고 `validate`가 실행되지 않아 잔여석 에러 메시지가 뜨지 않는 문제가 있었습니다. 레이어를 명확히 분리하는 것으로 해결했습니다.

---

### 6. ParticipantList 동기화 문제 해결

`useFieldArray`의 `append/remove`를 반복 호출하는 방식은 `fields.length`를 의존성에 넣을 경우 루프가 발생하고, ref로 캡처해도 타이밍 불일치로 `4/3명` 같은 불일치 표시가 생겼습니다. 

`replace`로 원하는 크기의 배열을 한번에 교체하는 방식으로 변경했습니다. 기존 입력값은 인덱스 기준으로 보존하고 새로 추가되는 슬롯만 빈 값으로 채웁니다.
